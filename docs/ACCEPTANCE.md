## 5. 已知限制

1. Day 1～Day 2 只做解析与展示；Day 3 起补上了「缺失值 + 疑似重复记录 + 分析准入」这一部分数据质量诊断，但**不判断数值本身是否离谱**（异常值仍属 F3），也不做类型不一致与质量评分
2. 接近 5 MB 上限的文件（实测 4.58 MB / 239,153 行）会一次性读入内存并全量持有行数组，解析耗时约 2 s；渲染已改为每批 50 行，内存占用仍与文件行数成正比。错误密集的文件本轮已受控：5 万条缺列记录（379.8 KB）实测约 128 ms 出结果、结果卡片只有 549 个元素
3. 分隔符由 Papa Parse 自动检测（实测 `;` 文件按分号解析并提示），单列文件会退回默认逗号并给出 `notice`；`CsvTable.delimiter` 已带出实际使用的分隔符
4. 不支持 `.xlsx`、多文件、多 sheet
5. 行号是**物理行号**：由字符偏移换算（必要时多跑一趟 `step` 解析），跨行引号字段、被跳过的空行都 accounted for，已有用例覆盖（`[文件第 5 行]`、`[文件第 3–5 行]`）；`rowIndex` 仍保留为数据行下标兜底
6. **像素截图本轮才恢复，且只有一个宽度**：Day 1～Day 2 各轮的内置浏览器实例报 `viewport=0x0 / visibilityState=hidden`、`take_screenshot` 返回 `NATIVE_BROWSER_VIEWPORT_UNAVAILABLE`，那些结论只有 DOM / 计算样式 / 几何证据（见 2.1～2.3）。本轮（2.4）视口为真实的 633×665 并成功取得 2 张 PNG，但 1440 / 1280 / 375 px 的渲染至今没有任何像素证据，仍需你在真实浏览器里确认
7. 组件层已有 Testing Library（jsdom）测试：分批加载、拖拽热区、结果定位与播报、提示列表、错误明细逐批展开与英文原文折叠均受测；但 jsdom 不做真实布局，粘性表头遮挡靠 2.3 的浏览器几何测量、横向溢出提示本轮（2.4）已在真实 633 px 布局下验证（`scrollWidth 1874 > clientWidth 542` 时出现、无溢出时不出现），其余宽度仍需人工确认
8. 列对齐只是基于文本形状的**排版**判断（为控制开销，最多扫描每列前 1000 行），不是数据类型推断，也不参与任何质量结论；整列只要出现一个非数值就退回左对齐
9. 上传区域的空白处点击也会打开文件选择框（按钮同样可用）；如果不希望这样，需要去掉区域级 `onClick`
10. 品牌图形目前只有一处来源（`public/favicon.svg`），导航栏直接引用它；若后续要做深底/单色版本，需要另出图形
11. Tailwind v4 的自动内容扫描会把文档里写出的类名字面量当成真实用法，导致产物 CSS 随文档文字小幅变化（本次约 +0.06 kB）；这不是代码回归，若要产物稳定可在样式入口用 `@source` 显式限定扫描范围
12. LF/CRLF 混用时 Papa 按首个换行符切分，行末 `\r` 会留在该行最后一个单元格；界面只提示不加工，后续按数值解析时必须自行容忍
13. 「编码不支持」的判定只看首字符替换符与前 4096 字符内的 NUL，只用于拦住 UTF-16/UTF-32/二进制误传，不识别 GBK/Big5 等单字节编码（这类文件会被当作 UTF-8 读，中文表头可能变成替换符）
14. 存在需要定位行号的格式错误时会多跑一趟 Papa 换取真实物理行号；本轮把这趟限制在明细预算内（最多 200 条，读够就 `abort()`），5 万条错误实测约 128 ms 出结果。历史实测 26 万行错位文件全量一趟 183 ms 仍成立；如果以后放开 5 MB 上限，这趟仍需改为增量或与主解析合并
15. 重复表头时 Papa 自己会 `console.warn('Duplicate headers found and renamed.')`，属于第三方内部行为，界面已解释改名结果，但没有（也不应）去抑制它
16. 逐条明细每种来源最多 200 条（`MAX_ITEMIZED_ISSUES`）：超出部分只计入 `issueGroups[].total` 并在界面上明确写出「另有 N 条同类格式问题没有逐条列出」，界面按每批 20 条展开。总量与类型分布是全文件真实值，但 `table.issues` **不是**完整清单——后续若要导出全部错误，需要另做流式或分页导出，不能直接遍历这个数组
17. `table.structure.state`（`sound` / `degraded`）与 `reasons` 目前只被界面消费，还没有任何分析模块读取它；Day 3 质检引擎必须显式处理 `degraded`，否则缺列/丢值的数据仍可能被当作完整数据出统计结论**（Day 3 已落实：`evaluateQualityAdmission()` 同时读 `structure.state` 与 `issueTotals.errors`，`degraded` 与任何解析错误都阻止正式结论，见 2.5 与第 1 节 44～48 项）**
18. 表头真叫 `__parsed_extra` 且该行字段数多于表头时，Papa 会把多出的值追加进同一个内部桶，只能保留属于表头的第 1 个值，其余计入 `structure.droppedExtraValues`；这是解析器行为，界面用 `ParsedExtraHeaderCollision` 提示同名风险并建议用户改名
