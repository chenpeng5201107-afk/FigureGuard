# FigureGuard 产品需求文档（PRD）

版本：v0.3（Day 4：字段类型识别与类型冲突检测）　　更新日期：2026-11-17

## 1. 问题背景

大学生在实验课、科研训练和课程项目中经常需要提交数据表格和图表，但普遍缺少系统的质检习惯：

- 数据里存在空值、重复记录、单位不一致、明显离谱的数值，却没被发现
- 图表用了不合适的类型（例如用饼图表示时间序列）、坐标轴截断、缺少误差棒或图例
- 被老师或审稿人指出问题后，不知道该改哪里、为什么这样改

现有工具要么只做大模型「一句话点评」，要么是需要付费的专业软件，学生很难在写完实验报告的当天用上。

## 2. 目标用户

- 主要：需要提交实验报告、课程项目、毕设数据的本科生
- 次要：需要快速检查学生图表质量的教学助理和指导教师

## 3. 产品定位

一个**打开就能用、结论可解释**的科研图表质检 Web 应用：上传数据 → 检查数据 → 生成图表 → 诊断图表表达 → 对比修复前后 → 导出报告。

设计上坚持三点：

1. **真实计算**：所有数字都来自实际解析和统计，不编造结论
2. **过程可解释**：不仅说「有问题」，还说明问题在哪一行/哪一列、依据是什么
3. **零门槛**：纯前端，不需要注册、不需要上传数据到服务器

### 4.2 Day 1 交付范围（已验收）

**用户故事**：作为第一次接触 FigureGuard 的学生，我希望能立刻看到产品能做什么，并用自己手头的数据验证它是否真的能读懂 CSV。

需求清单：

- R1 首页展示品牌名 FigureGuard、中文副标题「科研图表急救室」和产品核心价值
- R2 支持点击选择或拖拽方式上传本地 `.csv` 文件
- R3 提供「体验示例数据」按钮，无需自备文件即可看到效果
- R4 解析成功后以表格展示数据，并显示**真实**的记录数、字段数、数据体积、来源
- R5 解析失败或格式异常时，显示 Papa Parse 返回的实际错误与告警，并定位到文件行号
- R6 文件大小上限 5 MB，超限给出明确提示而不是静默失败
- R7 数据只在浏览器本地处理，界面上明确告知用户
- R8 内置示例数据必须标注「合成的演示数据」，避免被误认为真实实验结果
- R9 页面在桌面端和移动端都能正常使用
- R10 界面上不出现当前还没有实现的功能入口

### 4.3 Day 3 交付范围（本期实现：数据质量诊断引擎 V1）

**用户故事**：作为要把实验数据交给老师检查的学生，我希望在画图和分析之前先知道「这份数据里有没有漏填的空格、有没有整行重复的记录」，并且知道这些结论是怎么算出来的；如果数据本身读错位了，我要清楚现在为什么不能给我质量结论，而不是一边看到假统计一边毫不知情。

需求清单：

- R11 有明确的数据质量分析**准入判断**：行列结构降级（`structure.state = 'degraded'`）或存在任何 `error` 级解析问题时，不输出正式质量结论
- R12 被阻止分析时仍然可以浏览原始数据表格与解析告警，并说明原因、影响与怎么修（不得静默忽略解析错误）
- R13 缺失值统计四套口径分开：空字符串（缺失）、只有空白字符（疑似空白值，不并入缺失）、`null`（结构性缺列）、`'0'` 等文本（实际内容，不算缺失）
- R14 输出总记录数、逐列缺失数量与缺失率、全表缺失单元格数、需要关注的字段；`recordCount = 0` 时不得出现除零 / `NaN` / `Infinity`
- R15 完全重复记录检测：整行逐字段相等才算重复；单次扫描 + Map，不做 O(n²) 两两比较；分开报告重复组数、涉及记录数、额外副本数，并记录每组的原始数据行序号
- R16 `sample_id` 不同但测量值相同的两行不得被判为完全重复；界面对重复一律使用「疑似重复记录，请人工确认」的谨慎措辞，不宣称已删除
- R17 诊断全程**只读**：不填充、不删除、不排序、不修改 `CsvTable.rows`（由引用相等 + JSON 快照两类断言守住）
- R18 预览区新增「数据质量概览」分区（四项统计 + 精简问题列表），与原始表格分区共存；数字全部来自真实规则计算，无硬编码；问题列表首屏少量、逐批展开
- R19 换成另一份文件时诊断结果与展开状态全部重置，不串用上一份的统计
- R20 明细有上限但总量全量准确：重复组 200 组、问题条目 100 条、界面每批 5 条；超出部分必须显式说明，不得静默丢弃
- R21 手机端不出现页面级横向溢出（宽表溢出关在表格自己的滚动容器里）
- R22 本期不做的能力不得出现在界面上（异常值、图表表达诊断、修复对比、导出、自动清洗）

### 4.4 非目标（本期明确不做）

- 不做数据质量评分、异常值判定（评分属 F2 后续，异常值属 F3）
- 不做缺失值自动填充、重复记录自动删除、任何改写用户数据的「一键清洗」
- 不做同一列类型不一致检测（需要先补列类型推断）
- 不做图表表达诊断（F5）、修复前后对比（F6）与折线图 / 误差棒（图表仅 V1：柱状图 / 散点图逐条原始记录绘制，见 F4）
- 不做报告导出（属于 F7）
- 不做多文件、多 sheet、Excel 原生 `.xlsx` 解析
- 不做用户系统、云端存储、协作

## 5. 关键交互与边界情况

| 场景 | 期望行为 |
| --- | --- |
| 空文件（0 字节 / 只有空白行） | 提示「CSV 文件内容为空」 |
| 只有表头行 | 正常解析，显示 0 条记录和字段数 |
| 首行没有字段名 | 提示「未识别到表头行」 |
| 某些行字段数多于/少于表头 | 保留可解析的数据，列出告警并指出文件行号 |
| 单元格为空 | 原样显示为空，不填充 0 或臆测值 |
| 缺列 | 显示「—」并说明该行字段数少于表头 |
| 文件 > 5 MB | 拒绝解析，提示精简或拆分 |
| 非 `.csv` 扩展名 | 拒绝并提示另存为 CSV |
| 记录数 > 50 | 默认显示前 50 条，可展开全部 |
| 中文与 UTF-8 内容 | 正常解析，体积按 UTF-8 字节计算 |
| 单元格只有空格 / 制表符 | 标记为「疑似空白值」，单列计数，不并入缺失单元格数量 |
| 数值 `0`、文本 `0.0`、`-0` | 按实际内容处理，不计入任何缺失口径 |
| 只有表头、没有数据行 | 统计照常出：0 行、0 个缺失、比率按 0 处理并明确说明「没有数据行可分析」，不做除零 |
| 整行字段完全相同的记录 | 报告为「疑似重复记录」，给出数据行序号，不删除、不改写，措辞要求人工确认 |
| 只有 2 行测量值相同但 `sample_id` 不同 | 不判为重复（判定口径是整行每个字段都一致） |
| 缺列（该行字段数少于表头） | 计入「结构性缺列」，与空单元格分开；同时让结构降级，阻止正式质量结论 |
| 引号未闭合但字段数仍匹配（`a` + `"foo`） | `structure.state` 仍是 `sound`，但 `issueTotals.errors > 0` → 质量分析准入不通过，界面解释原因 |
| 上万行的高度重复 | 重复检查仍单次扫描完成，明细最多 200 组，总组数 / 涉及行数 / 额外副本数为全量真实值 |
| 问题条目很多 | 首屏 5 条，按每批 5 条展开；一次生成最多 100 条，折叠部分明确写出「另有 N 组…没有逐条列出」 |
| 连续上传两份文件 | 质量统计与展开状态全部重置，不残留上一份的数字 |

## 7. 后续待明确的问题

- 5 MB 上限是否需要在界面上可调（大文件是否需要流式解析）
- 异常值判定默认用 IQR 还是 Z-score，是否允许用户选择
- 图表诊断规则是否要区分「错误」和「建议」两个严重级别
- 导出格式优先 Markdown、PDF 还是图片
- 质量分析的准入要不要留「仍然查看统计」的逃生入口（当前是全有或全无：1 行缺列的文件完全没有统计卡）
- 缺失率阈值 10% 是否需要可调，或按「列的重要程度」区分（例如 `sample_id` 缺失比测量值缺失更严重）
- 疑似空白值是并入缺失数量，还是始终单列（当前单列）
- 近似重复（大小写、多余空格、同一 `sample_id` 的多次录入）是否要在 F2 剩余部分补上
- 问题条目能否点击定位到表格对应单元格并高亮（本期只给数据行序号）
