# FigureGuard 产品需求文档（PRD）

版本：v0.1（Day 1）　　更新日期：2026-11-16

## 1. 问题背景

大学生在实验课、科研训练和课程项目中经常需要提交数据表格和图表，但普遍缺少系统的质检习惯：

- 数据里存在空值、重复记录、单位不一致、明显离谱的数值，却没被发现
- 图表用了不合适的类型（例如用饼图表示时间序列）、坐标轴截断、缺少误差棒或图例
- 被老师或审稿人指出问题后，不知道该改哪里、为什么这样改

现有工具要么只做大模型「一句话点评」，要么是需要付费的专业软件，学生很难在写完实验报告的当天用上。

## 2. 目标用户

- 主要：需要提交实验报告、课程项目、毕设数据的本科生
- 次要：需要快速检查学生图表质量的教学助理和指导教师

## 3. 产品定位

一个**打开就能用、结论可解释**的科研图表质检 Web 应用：上传数据 → 检查数据 → 生成图表 → 诊断图表表达 → 对比修复前后 → 导出报告。

设计上坚持三点：

1. **真实计算**：所有数字都来自实际解析和统计，不编造结论
2. **过程可解释**：不仅说「有问题」，还说明问题在哪一行/哪一列、依据是什么
3. **零门槛**：纯前端，不需要注册、不需要上传数据到服务器

### 4.2 Day 1 交付范围（本期实现）

**用户故事**：作为第一次接触 FigureGuard 的学生，我希望能立刻看到产品能做什么，并用自己手头的数据验证它是否真的能读懂 CSV。

需求清单：

- R1 首页展示品牌名 FigureGuard、中文副标题「科研图表急救室」和产品核心价值
- R2 支持点击选择或拖拽方式上传本地 `.csv` 文件
- R3 提供「体验示例数据」按钮，无需自备文件即可看到效果
- R4 解析成功后以表格展示数据，并显示**真实**的记录数、字段数、数据体积、来源
- R5 解析失败或格式异常时，显示 Papa Parse 返回的实际错误与告警，并定位到文件行号
- R6 文件大小上限 5 MB，超限给出明确提示而不是静默失败
- R7 数据只在浏览器本地处理，界面上明确告知用户
- R8 内置示例数据必须标注「合成的演示数据」，避免被误认为真实实验结果
- R9 页面在桌面端和移动端都能正常使用
- R10 界面上不出现当前还没有实现的功能入口

### 4.3 非目标（本期明确不做）

- 不做数据质量评分、异常值判定（属于 F2/F3）
- 不做图表绘制与诊断（属于 F4/F5）
- 不做报告导出（属于 F7）
- 不做多文件、多 sheet、Excel 原生 `.xlsx` 解析
- 不做用户系统、云端存储、协作

## 5. 关键交互与边界情况

| 场景 | 期望行为 |
| --- | --- |
| 空文件（0 字节 / 只有空白行） | 提示「CSV 文件内容为空」 |
| 只有表头行 | 正常解析，显示 0 条记录和字段数 |
| 首行没有字段名 | 提示「未识别到表头行」 |
| 某些行字段数多于/少于表头 | 保留可解析的数据，列出告警并指出文件行号 |
| 单元格为空 | 原样显示为空，不填充 0 或臆测值 |
| 缺列 | 显示「—」并说明该行字段数少于表头 |
| 文件 > 5 MB | 拒绝解析，提示精简或拆分 |
| 非 `.csv` 扩展名 | 拒绝并提示另存为 CSV |
| 记录数 > 50 | 默认显示前 50 条，可展开全部 |
| 中文与 UTF-8 内容 | 正常解析，体积按 UTF-8 字节计算 |

## 6. 成功标准（Day 1）

1. `npm run dev` 可启动，首页无控制台报错
2. `npm run build` 与 `npm test` 全部通过
3. 示例数据和用户 CSV 都能正确显示记录数与字段数，数字与文件实际内容一致
4. 至少覆盖正常解析、空文件、记录数统计三类单元测试
5. 页面在窄屏（约 375 px）下可完成上传与查看表格
6. 部署产物 `dist/` 可在 Qoder Sites 正常访问

## 7. 后续待明确的问题

- 5 MB 上限是否需要在界面上可调（大文件是否需要流式解析）
- 异常值判定默认用 IQR 还是 Z-score，是否允许用户选择
- 图表诊断规则是否要区分「错误」和「建议」两个严重级别
- 导出格式优先 Markdown、PDF 还是图片
